# NPCs tripulantes: plano de implementação

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 1 a 3 NPCs tripulantes que consomem o estoque da base, operam estações (estufa, reciclador de água, gerador de O2), avisam o líder e recebem ordens (F de perto, C no painel).

**Architecture:** Lógica pura em `src/crew/` (sem Three.js/DOM, testada com Vitest) + `CrewAvatar` (Three.js) seguindo trilhos fixos + `CrewPanel` (DOM). Integração em `GameEngine`. A branch é baseada no PR #44: energia = `MissionSystem.battery`, e o O2 do habitat é pago pela bateria.

**Tech Stack:** JavaScript ES modules, Three.js 0.181, Vite 6, Vitest.

## Global Constraints

- Textos da UI em inglês, linguagem para 7 a 12 anos, sem emoji.
- Todo número de balanceamento em `src/config/constants.js` (`CREW_CONFIG`, `STATION_CONFIG`).
- Proporção água:comida por tripulante = NASA BVAD (~3 kg : ~1,8 kg por pessoa/dia).
- Nenhuma ordem é de graça: trabalhar gasta energia, e todo tripulante consome O2 (energia), água e comida.
- Só estações com operador emitem aviso (cooldown `ALERT_COOLDOWN_S`).
- Sem morte de NPC: `weak` → `evacuated` após `EVACUATE_AFTER_HOURS` seguidas sem recurso.
- `npm test` e `npm run build` verdes a cada commit.

## Ajustes em relação à spec (decorrentes do código do PR #44)

- O PR #44 já paga o O2 do habitat com bateria. Então o **O2 do tripulante custa energia** (`OXYGEN_ENERGY_PER_HOUR`), não um estoque de O2 separado.
- Estações usam um modelo de **manutenção**: `health` cai sem operador e sobe com operador (que gasta energia). Efeitos:
  - Estufa: produz comida para a tripulação (×health, só com água na irrigação).
  - Reciclador: devolve 98% da "água cinza" da tripulação ao tanque ([Ref] ISS Water Recovery System).
  - Gerador de O2: `health` baixa encarece o O2 (até 2×) para o jogador **e** para a tripulação (filtros saturados).
- O contrato vira `update(hours, workers, base)` (com `produce` interno), `problems(base)` e `canOperate(base)`.
- Evacuação em **horas de jogo** (`EVACUATE_AFTER_HOURS = 12`, ~10 min reais) em vez de 2 sols (~40 min), para caber numa partida.

### Task 2: Estações

**Interfaces (produz):**
- `class Station { id, kind, name, workNode, health, operating; canOperate(base); update(hours, workers, base); problems(base): string[] }`
- `Greenhouse`, `WaterRecycler`, `OxygenGenerator extends Station`; `OxygenGenerator#costMultiplier(): number`
- `createStations(): Station[]` (uma de cada tipo)
- `problemText(station, problem): string`
- `base` = `{ battery: Battery, water, maxWater, hydration, food, maxFood, graywater }`

- [ ] Testes:
  - sem operador, a `health` cai `DEGRADE_PER_HOUR`; com operador, sobe e gasta `WORK_ENERGY_PER_HOUR`;
  - sem bateria, não opera (`canOperate` false) e degrada;
  - a estufa produz comida só com `hydration >= GREENHOUSE_MIN_HYDRATION` e respeita `maxFood`;
  - o reciclador converte água cinza em água a 98%, limitado pela taxa e por `maxWater`;
  - `costMultiplier` vai de 1 (health 1) a `OXYGEN_MAX_COST_MULTIPLIER` (health 0);
  - `problems` lista `no-power`, `needs-care`, `no-water` (estufa) e `tank-low` (reciclador).
- [ ] Falhar → implementar → passar → commit `feat(crew): add base stations with maintenance model`.

### Task 3: CrewManager

**Interfaces:**
- Consome: Tasks 1 e 2.
- Produz:
  - `new CrewManager({ size, stations, base })`
  - `.members: CrewMember[]`, `.stations`
  - `.assign(memberId, task): { ok: true, message } | { ok: false, reason }`
  - `.update(hours, nowSeconds)`: avança em passos de até `MAX_STEP_HOURS`
  - `.updateMovement(dtSeconds)`
  - `.oxygenCostMultiplier(): number`
  - `.workersAt(station): CrewMember[]`
  - `.drainEvents(): Array<{type:'weak'|'recovered'|'evacuated'|'alert', member, station?, problem?, lacking?}>`
- `CrewMember { id, name, task, state: 'idle'|'walking'|'working'|'resting'|'weak'|'evacuated', node, route, distance, hoursStarved }`

- [ ] Testes:
  - o consumo escala com o tamanho da tripulação;
  - a falta de comida/água/energia deixa o NPC `weak` e emite o evento com `lacking`;
  - `weak` volta quando o recurso volta;
  - evacua em `EVACUATE_AFTER_HOURS` (sem resetar antes);
  - `assign` recusa estação sem energia e tripulante evacuado;
  - andar até a estação leva `routeLength / WALK_SPEED` segundos e termina `working`;
  - só quem está `working` conta como operador;
  - o aviso sai só de estação com operador e respeita o cooldown;
  - o multiplicador de O2 vem do gerador e encarece o O2 da tripulação.
- [ ] Falhar → implementar → passar → commit `feat(crew): add crew manager with needs, orders and alerts`.
